# CLI research (`svelters` command)

Written incrementally by the CLI research lane (2026-10-17). Design proposal: `plans/research/CLI.md`.

## 1. Inventory: what a CLI would wrap

### Build (stock Svelte path)
- `packages/build/index.js` `svelteConfig(root, backend, options)`: Vite config, output `dist/app.js` (single
  self-contained ESM, no imports) + `dist/app.js.map`. `backend` = `renderer` (default, vendored fork of Svelte
  PR #18042, `vendor/svelte/PIN`) or `shim` (`@svelters/dom`), chosen by `SVELTERS_BACKEND`. `options.style`
  = `{strict, verbose, tokens}` for the style plugin (`packages/build/style-plugin.js`).
- `packages/build/bin/svelters-build.mjs`: `svelters-build [--watch] [dir]`, runs Vite with the app's own
  `vite.config.js`; `--watch` = Vite build-watch without emptying `dist/` (so a watching host never sees a
  missing bundle). Root `pnpm watch` wraps it.
- **The bundle is toolkit-neutral today.** The toolkit is picked at run time (`counter --backend gtk|qt`).
  Element names are portable tags (`window`, `box`, `label`); after N1 they become native kebab names per
  toolkit, so the bundle (and its typings) become per-toolkit.
- Apps today are `fixtures/<name>/` (package.json + vite.config.js + src/App.svelte + src/main.js), e.g.
  `fixtures/counter`, `fixtures/gallery-gtk`, `fixtures/gallery-qt`. `fixtures/README.md`.
- Typings: `packages/renderer/types/{index,gtk,qt,bindings,menus,values,native}.d.ts`; `gtk.d.ts` from
  `tools/metadata/gtk/gen_backend.py`, `qt.d.ts` from `tools/metadata/qt/gen_cpp.py` via
  `examples/counter-qt/build.rs`. An app opts in with `"types": ["@svelters/renderer/types"]`; both toolkits
  are in one union today. svelte-check config sample: `packages/renderer/check/`.
- Node TestHost: `packages/testhost/bin/svelters-test.mjs` (op-log tests: `script.json` + `expected.oplog`).

### Build (native compiler path, PR #3 / NC1, merging in ST1)
- `crates/svelters-compiler` (on `pr-3`), bin `svelters-compile --backend gtk|qt [--spec spec.json] [--dev]
  [--module] [--json] <file|->`, prints JS or `{js,map,diagnostics,backend,timings}`.
- `packages/native-runtime` (`@svelters/native-runtime`, exports `.`, `./lists`, `./vite`);
  `@svelters/native-runtime/vite` gives `nativeConfig(dir, {entry, outDir, plugins})` and
  `svelteNative({backend, spec})` (Vite plugin shelling to the compiler). Example driver:
  `experiments/native-compiler/compiled/build.mjs`.
- **Compiles per toolkit** (semantic spec `metadata/semantics/{gtk,qt}.json`, generated by
  `tools/metadata/semantics/gen_semantics.py` from `metadata/semantics/rules/*.yaml`), so this path already
  needs the toolkit at build time. Needs a built `svelters-compile` binary (ST1 gate: `pnpm test` must not
  require one).

### Host / run
- `crates/svelters-host` (rquickjs, job pump, timers, console, source maps, handle table, hot reload in
  `reload.rs`, `sourcemap.rs`; `Host::watch/on_reload/request_reload`). ABI `crates/svelters-abi`.
- Backends: `crates/svelters-gtk` (gtk4-rs, Rust) and the Qt backend as generated C++ compiled by a **leaf
  crate** `examples/counter-qt` (`build.rs` -> `crates/svelters-qt-build`, needs Qt 6 dev headers + C++
  toolchain). `crates/svelters-backend-log` = log backend.
- The only runner binary is `examples/counter` (`src/main.rs`):
  `counter --backend gtk|qt [--fixture <name|dir>] [--script s.json] [--screenshot png] [--report json]
  [--end quit|close] [--timing] [--timeout secs] [--watch [--reload-exit n]]`. Features `gtk`,`qt`.
  `--fixture` resolves `fixtures/<name>/dist/app.js`. Driver (`driver.rs`) can script/screenshot/report:
  that is the seed of `svelters run --script`/`inspect`.
- Dev loop (M2b, `docs/notes/m2b-devloop.md`): two processes: `pnpm watch fixtures/<app>` (Vite watch) +
  `counter --backend X --fixture <app> --watch` (inotify on dist/, 120 ms debounce, load-new-then-destroy-old,
  failed load keeps old UI, errors mapped to `.svelte:L:C`). Edit -> new UI ~1.7-2 s. A CLI `dev` command
  = spawn both and multiplex logs.
- Cargo builds go through `tools/dev/cargo-slot` in this repo (agent rule); a CLI must not rebuild Rust on a
  `.svelte` edit (PLAN rule 5).

### Metadata
- Ingested per class JSON: `metadata/gtk/*.json` (GIR), `metadata/qt/*.json` (qdoc/metaobject/typesystem).
- Hand/agent annotations: `metadata/overrides/{gtk,qt}/<Class>.yaml` (`elements: - tag: window, construct,
  props {js,native,provenance}, methods, signals, children {policy, default_slot, slots[...]}`), schema
  `tools/metadata/qt/override.schema.json`.
- Verified facts `metadata/verified/<tk>.json`; coverage `metadata/coverage/{gtk,qt}.{json,md}`;
  ingested upstream doc text `metadata/docs/{gtk,qt}/`. Extras: `metadata/extras/gtk-menus.yaml`.
- Tools: `tools/metadata/{common,gtk,qt,style,docs}`, `ledger.py`, `coverage.py`; gate `pnpm test:meta`.

### Docs generator (D1) -- the natural data source for `svelters docs`
- `tools/docs/build_ir.py` runs `tools/docs/<tk>/frontend.py` -> **`docs/site/.generated/ir/<tk>.json`**
  (not checked in; ~7.0 MB gtk, ~6.8 MB qt). Schema `tools/docs/ir/schema.json` ("toolkit-neutral docs IR",
  one doc per toolkit), lib `tools/docs/ir/irlib.py`.
- IR top level: `{schema, toolkit{id,name,version,doc_license,text_policy,upstream_docs,...}, entities[],
  coverage, extension_schemas}`. Qt: 416 entities (192 class, 224 enum).
- Entity: `id` (`qt:QMainWindow`), `kind`, `name`, `native_name`, `tags` (Svelte element tags, e.g.
  `["window"]`), `status{tier,tested,metadata_file,annotation_files}`, `summary`, `description`, `bases`
  (nearest first), `interfaces`, `properties[]`, `events[]`, `methods[]`, `constructors[]`, `values[]`
  (enums), `children{policy,default_slot,slots[]}`, `examples[]`, `lifetime`, `screenshot`, `serdes`,
  `see_also`, `abi_symbols`, `extensions.<tk>`.
- Property: `js_name,name,type{display,native,ref,nullable,neutral},default,range,access{read,write},notify,
  bindable,accessors{get,set},doc{md,license,truncated,upstream_url},annotated,verified,origin(s)`.
- Event: `js_event, handler_prop (onclose-request), handler_aliases, params, returns, handler_result,
  sync_required, phase, flags`.
- Slot: `name, cardinality, accepts[], default, order, ops{get,set,remove}, ownership, on_remove, attrs[]
  (child attrs), verified, provenance`.
- Example: `title, lang, code, generated, tested`.
- Site: `docs/site` (Astro Starlight), pages generated by `docs/site/scripts/gen-pages.mjs` +
  `lib/render.mjs` with sections Usage / Inheritance / Description / Values / Properties (+ inherited block) /
  Events / Children and slots / Lifetime / Constructors / Methods / <extension> / See also. API pages per tag
  `docs/site/src/content/docs/api/<tk>/<tag>.md` + `api/matrix.md`. Guides incl. `guides/styling.md`.
- **Licensing constraint:** Qt doc text is GFDL, IR `text_policy: brief` (only briefs reproduced). Shipping the
  IR inside a CLI package is redistribution: keep the same brief-only policy and the attribution notice.
- **Not yet in the IR:** style properties. ST1 adds `metadata/style/{gtk,qt}.yaml` (in progress in the ST1
  worktree): `toolkit, dialect (css|qss|none), setter_selectors, units, properties{name: {via: css|setter|
  child-attr, prop|attr, type, kinds|parents, note, inline_only}}`; ST1 design item 6 makes the doc
  generator emit a styling reference from it. The CLI should consume that same generated output.

### Styling today
- `packages/style/src/{vocab,translate,decls,runtime,tokens,kinds.generated}.js`; `vocab.js` `MATRIX`
  (portable names, gtk/qt yes/no) is replaced by the ST1 tables.

### Gap found while inventorying (to verify, not fixed here)
- The on-disk Qt IR (`docs/site/.generated/ir/qt.json`, generated 2026-10-17 02:11) has only **8** entities
  with `tags` (label, entry, window, menubar, button, scrolledwindow, statusbar, box), while
  `metadata/overrides/qt/*.yaml` declare **57** `- tag:` elements in 54 files (A1 reports Qt 52/77
  elements). GTK IR has 101 tagged entities. `tools/docs/qt/frontend.py:135` `elements_for` matches only on
  `construct.class`. Either the IR is stale or the frontend misses most elements; a docs CLI built on the IR
  inherits whichever it is. Fix (or regenerate) before shipping `svelters docs`.
- Element tag names in the IR are still portable (`window`, `box`, `scrolledwindow`); N1 renames them.
  Several native classes share a tag across toolkits (`window` = GtkApplicationWindow / QMainWindow;
  Qt `box` = QWidget+QBoxLayout).

## 2. Prior art

### create / dev / build
- **`sv`** (https://svelte.dev/docs/cli/overview): `npx sv create [--template] [--types] [--add ...]`,
  `sv add <addon>[=opts]` for post-hoc integrations (tailwind, vitest, ...), `sv check`, `sv migrate`.
  Take: `create` + `add` symmetry, every interactive question also a flag (`--no-interactive` for agents),
  add-ons as composable file edits, `sv add ai-tools` writes agent setup (MCP config local/remote, agent
  README linked to AGENTS.md, skills) -- https://svelte.dev/docs/cli/mcp (page is the ai-tools add-on).
- **Tauri** (`create-tauri-app`, https://tauri.app/reference/cli/): `tauri init|dev|build|bundle|info|add|
  icon|migrate`. Take: `info` (environment/doctor dump, pasteable into bug reports), `dev` spawning the
  frontend dev command + native process together, `build` -> `bundle` (deb/rpm/AppImage), CLI distributed
  both as npm package (Rust binary per platform) and `cargo install tauri-cli`.
- **Cargo** subcommands: external `cargo-<x>` on PATH become `cargo x`. Take: `svelters-<x>` extension
  hook later; `--message-format json` style machine output for every command.
- **Expo CLI**: `npx expo start` with a key-driven dev console (r reload, j debugger), `expo install` that
  picks versions compatible with the SDK, `expo doctor`. Take: version-aligned `add`, single `dev` console.
- **Flutter**: `flutter create --platforms`, `flutter doctor -v` (checklist with fix hints per toolchain),
  `flutter run` (hot reload `r`, hot restart `R`), `flutter build linux`. Take: doctor's checklist format
  with remediation commands; per-target `build`.
- **esbuild / biome / turbo** packaging: npm wrapper + per-platform `optionalDependencies` holding the
  native binary. Proven way to ship Rust binaries through npm.

### docs for agents
- **`go doc`** (`go doc pkg`, `go doc pkg.Sym`, `go doc pkg.Type.Method`, `-all`, `-src`, `-short`): one
  dotted address space, terse by default, `-all` expands. Case-insensitive match, falls back to search.
  Closest model for `svelters docs qt main-window.title`.
- **`ri`** (Ruby): `ri String#upcase` (instance), `ri File::open` (class), lists candidates when ambiguous,
  `--format=markdown`. Take: sigil-qualified member kinds only when needed for disambiguation.
- **`man`**: sections (`man 3 printf`), `apropos`/`man -k` search. Take: section selectors and `-k` search.
- **`rustup doc --std`, `cargo doc --open`**: open local HTML; not agent friendly (HTML, browser). Avoid as
  the primary agent path; keep `--open` as a human convenience pointing at the site page.
- **llms.txt** (https://llmstxt.org/): `/llms.txt` markdown index (H1, summary blockquote, H2 link lists,
  "Optional" section), plus `.md` variants of each page. Svelte publishes `llms.txt`, `llms-full.txt`,
  `llms-small.txt`. Take: the docs site should emit `llms.txt` + per-page `.md` from the same IR; the CLI
  is the offline equivalent.
- **Svelte MCP server** (https://svelte.dev/docs/mcp/tools): tools `list-sections`, `get-documentation`
  (sections), `svelte-autofixer` (static analysis loop until clean), `playground-link`. Take: two-step
  list-then-fetch to keep context small; a checker tool agents can loop on (our `check`).
- **Context7 / docs MCPs** generally: `resolve-library-id` then `get-library-docs(topic, tokens)`; token
  budgets as a parameter. Take: `--brief` / max-size control.
- **AGENTS.md** (agents.md): plain markdown at repo root read by most coding agents; Claude Code reads
  CLAUDE.md, which can import `@AGENTS.md`.

### Dependency fetching facts
- The Svelte fork is a vendored tarball `vendor/svelte/svelte-5.57.2-27b7dfb.tgz`, forced workspace-wide by
  an override in `pnpm-workspace.yaml:10`. `vendor/svelte/PIN` says the fork branch is "not pushed" while
  `plans/STATUS.md` F1 says pushed to akiselev/svelte; either way there is **no published package** an
  outside project can depend on. A scaffold outside the repo needs one (npm alias
  `"svelte": "npm:@svelters/svelte@5.57.2-cr.N"` or a tarball URL on a GitHub release) plus a matching
  `overrides`/`pnpm.overrides` so `@sveltejs/vite-plugin-svelte` resolves the same copy.
- `@svelters/*` packages are all `private: true`, version 0.0.0, `workspace:*`. Nothing is published.
- Runner: only `examples/counter` (GTK via gtk4-rs; Qt via the `counter-qt` leaf crate compiling generated
  C++ against system Qt 6). No generic "load this bundle path" runner, no prebuilt binaries.

## 3. Design decisions (summary; full text in plans/research/CLI.md)
- Docs probe reads a "docs pack" derived from the same IR the site uses (`docs/site/.generated/ir`), so CLI and
  site cannot drift; style data enters the IR via ST1 item 6.
- Language: Node/TypeScript CLI (`@svelters/cli`, bin `svelters`) orchestrating Rust artefacts (runner per
  toolkit, `svelters-compile`) shipped as per-platform npm packages; `cargo` source build as fallback.
  Reasons: every frontend needs Vite/Node already; the site renderer (`docs/site/scripts/lib/render.mjs`) and
  MCP SDK are JS; a Rust CLI would still have to spawn Node for every build.
- MVP = `docs` (works today on the IR) + `create/dev/build/run/doctor` in-repo; MCP, `add`, inspect,
  package later.
