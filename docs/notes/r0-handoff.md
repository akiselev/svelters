## Design decisions / deviations from §4/§13

- Observe facts are a separate layer stack merged into `metadata/observe/<tk>.json`, not fields of
  `metadata/<tk>/*.json`: GTK `ingest.py` needs PyGObject (absent here) and a prop fact's fingerprint covers its whole
  record (merging would invalidate all verified prop facts). The "ingested layer" is the raw rule inputs.
- `missed` vocabulary adds `programmatic` and `cross_prop`; a `verify` block (instance type + check) is part of the
  record; `origin` is per-provenance-entry.
- **GtkRange:fill-level does notify**: the research finding was a probe artifact (`c+1` next to G_MAXDOUBLE).
  REACTIVITY §3.1/§11 updated.
- `fires: on_set|on_change` decided by probe; EXPLICIT_NOTIFY wrong as a predictor for 39/557.
- Read-only GTK props never seen changing stay at 0.8 (review), except `:n-items` (accept pattern) — §13 #8 wants
  `exact` reliable, so no blanket rule.
- Qt O4 events / bindable / signal mechanisms are facts but untested until R3; WinUI ActualWidth/Height/Theme via
  events from the `no_notify` deny list (§11 item 4); AppKit value props partial user_edit unless a class fallback.
- §11 item 1 confirmed: fix 6bc336f1, test `types_core::detailed_notify_on_non_widget_objects` exists (not re-run).

  After unparking or a refresh that parked nothing, rerun gen_semantics/gen_bindings yourself (refresh regenerates only
