# A1 qt-dialogs notes

- `QDialog.yaml` carries an `inherit:` block (modal, sizeGripEnabled, accepted/rejected/finished, open/accept/reject/done), so every dialog kind gets them. `exec()` and the static helpers are never exposed.
- Gap (generator): `accept()`/`done(int)` are public on QDialog but protected in QColorDialog, QErrorMessage, QFileDialog, QFontDialog, QWizard. Generated method thunks call them on the subclass pointer and fail to compile, so those elements `exclude:` the method. Signal triggers use `static_cast<QDialog*>($w)->accept()` (virtual, public through the base). A generator fix (call through `QDialog*`) would restore them.
- Ingest quirk: `QInputDialog::doubleValue` is typed `i32` in `metadata/qt/QInputDialog.json` (should be double); the generated test fails, so the prop is dropped. `QWizard::startId` reads -1/first page, not what was set, so it is dropped.
- Triggers that needed care: QFileDialog `accepted` needs AnyFile mode + `selectFile()` before `accept()`; QProgressDialog `canceled` fires from the cancel button (`cancel()` does not emit it); QWizard `currentIdChanged` only fires through `restart()`/`next()` on an unshown wizard (`setCurrentId` is silent there); QColorDialog `currentColorChanged` trigger must alternate colours (3 emissions).
- Gap G9 (new): the Svelte side cannot mount a toplevel other than `<window>` (dom `childAttached` inserts any other element into its parent's layout, which would show the dialog) and cannot call element methods (bind:this forbidden). The gallery page 09-dialogs documents the surface with labels only.
