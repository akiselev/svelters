# Fixtures

Each fixture: `src/App.svelte`, `script.json` (steps), `expected.oplog` (byte-exact op log). `pnpm build` compiles it with `svelters-compile` (`@svelters/build`, so `cargo build -p svelters-compiler --bin svelters-compile` first) into `dist/app.js`; `pnpm test` builds and compares. Regenerate a log with `UPDATE=1 pnpm test` inside the fixture, then review the diff. The logs were regenerated on the compiled path in RT1 (state-equal with the retired renderer's at every boundary; the differences are listed in `plans/milestones/RT1-retire-fork-runtime-core.md`).

- `counter`, `keyed-list`, `if-toggle`: interaction and tree ops.
- `native-close`: a child window closed natively (`{"gone": [5, "closed"]}` in the script), then toggled by the app; the log shows `gone` lines and no ops for the dead handles, and the app reads the death reason (`parent`) from its `bind:this` node of the child label.
- `timers`: `setTimeout` + promise chain updating a label (for the host job pump).
- `bind-this`, `bind-value`: element `bind:this` (native `getProp`/`call` through the node, `StaleHandleError` after destroy) and `bind:text` on an entry with echo suppression. The TestHost does not model natively typed text, so its log shows the seed text where the real toolkits (checked by `examples/counter/tests/integration.rs`) read the typed text.
- `sync-handlers`, `listen-phases`: `close-request` and (on an `<event-controller-key>` attached to an entry, GTK vocabulary since RT1) `key-pressed` handlers that decide through the event object (`preventDefault`, `result`), and the plain / capture / after listen phases; the log shows `sync`/`result` lines. The toolkits are covered by `crates/svelters-gtk/tests/{sync,host_sync}.rs` and `examples/counter-qt/tests/host_sync.rs`.
- `lists-recycle` (testhost and log backend): `<ListView>` row-slot semantics (row-local state kept across a rebind, list context in rows, bound rows following splices, `bind:selected`, `onactivate`, `scrollTo`, teardown of every slot); `script.json` drives the row lifecycle with `sync` steps, `script.deferred.json` (TestHost `deferred` steps, used by `experiments/native-compiler/compiled`) as deferred deliveries.

Fixtures are written in the GTK vocabulary. `<name>-qt` is the Qt twin of `<name>`: the same app and script in the Qt vocabulary (`main-window`, `box-layout direction=`, `push-button`, `line-edit` + `text-changed`, `scroll-area`, `grid-layout`, `menu title=` / `action text=` + `triggered`), with `"svelters": { "toolkit": "qt" }` in `package.json` so the compiler targets the Qt spec and the TestHost uses the Qt prop schema and QSS dialect (`appkit` / `winui` likewise for `counter-mac`, `counter-win`, `gallery-appkit`). Also: `dialogs` (X7 toplevels declared anywhere, `show="none"`), `menus` / `menus-qt` (X4), `buffer-bind`, `child-attrs`, `styles`, `style-precedence`, `gtk-types`, `virtual-list`, `lists-stress`, and the galleries (`gallery-*`, screenshot tests in `examples/counter/tests/gallery.rs`). The Qt tests (`examples/counter-qt/tests`) run the twins' `dist/app.js` and `expected.oplog`; `experiments/native-compiler/compiled` compiles them for its qt target.
