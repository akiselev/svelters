## SV81: a dropped host frees its QuickJS runtime

**Bug.** `QjsCallbacks` (the callback table the core and ~21 JS closures hold as `Rc`) kept a
strong `rquickjs::Context`. The closures live in the runtime, the context keeps the runtime, so
`JS_FreeRuntime` never ran: every dropped `Host` kept its runtime (about 0.3 MiB bare, about
5.4 MiB with an app), and every full reload (`reload.rs`, `drop(old_engine)`) kept the old one.

**Fix** (`crates/svelters-host/src/quickjs.rs`).
- `QjsCallbacks::ctx` is `RefCell<Option<Context>>`. `QjsCallbacks::teardown` frees the node
  wrappers and the saved callback functions, then drops the context reference (idempotent).
- `QjsEngine::drop`: uninstall the fast ops, wait for transferred buffers (E2, unchanged; a
  runtime leaked on purpose still is), then clear the entry namespaces and tear the callbacks down
  while the runtime is alive. Dropping `ctx` and `rt` (the fields) then frees the runtime, whose
  closures release the last references to the table.
- After teardown, `invoke` fails with "host has shut down" and `free_released` does nothing.
- `Host::freed_runtimes()` (thread's count; incremented when the table is dropped after teardown,
  which only happens once the runtime freed its closures).

**Tests** (`crates/svelters-host/tests/teardown.rs`): 20 bare hosts created and dropped, 5 hosts
that ran an app (closures, a pending timer) dropped, 3 full reloads: each frees exactly one
runtime. QuickJS is built with `NDEBUG`, so a stray reference leaks rather than asserts.

## SV82: several backends over one document each get their own events

**Bug.** `SkelterBackend::shared` over one document, one host each: the document has one
`set_sync_delivery` slot (the last backend won) and one queue (`take_events`, `drain_changes`),
drained by whichever backend pumped first. A backend delivers only on nodes it holds handles for,
so the other hosts' events and native prop changes were dropped.

**Fix** (`crates/svelters-skelter/src/route.rs`, `deliver.rs`, `sync.rs`, `backend.rs`).
- Every backend joins its document's `Router` (one per document, found through a thread-local
  weak map). The router owns the sync-delivery slot.
- Ownership is the handle: a node belongs to the backend(s) holding a handle for it.
- An event's path is cut into runs of one owner, in path order; each run reaches its owner as an
  event of its own. Cancelable (sync) events: runs are delivered in order with the lent document;
  a stop ends the event, `preventDefault` in any run cancels the default.
- `dispatch`, `queue` and `pump` (via `collect`) route: this backend's part is delivered now; the
  others' parts go to their queues (`pending`) and they are woken (wake state and a frame request),
  so their next pump delivers them. Native prop changes go to every backend holding the node.
- One backend over a document: nothing is split, behaviour is unchanged.

**Tests** (`crates/svelters-skelter/tests/shared_document.rs`): one window, two panes, two backends
and two hosts mounting a counter. Clicks on both hosts' buttons dispatched through one backend
reach each host; events of both queued on one backend and pumped by it reach each host. Both
tests fail with routing switched off (checked) and pass with it.
