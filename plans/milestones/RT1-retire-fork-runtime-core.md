# RT1: retire the Svelte fork and the renderer path; runtime core phases 0 and 1

Status: DONE on branch `ci/rt1` (not merged; see the completion record).

## Scope

User decisions this milestone carries out:

- `plans/research/CLI.md` "Decisions (user, 2026-10-17)" 2 and 6: the Rust compiler
  (`crates/svelters-compiler`, `svelters-compile`) plus `@svelters/native-runtime` is the only
  frontend. The stock-Svelte + `@svelters/renderer` path and the Svelte fork are retired.
- `plans/research/RUNTIME.md` migration phases 0 and 1: native bundles and tests on stock
  `svelte@5.57.2`, CSS scoping off `experimental.customRenderer`, `tools/check-svelte-internals.mjs`;
  the compiler emits `@svelters/native-runtime/core`, which re-exports exactly the contract, and one
  adapter file is the only importer of `svelte/internal`.

Out of scope: RUNTIME phase 2+ (own reactivity core), the QuickJS dev module loader, the CLI.

## Decisions

1. **Order.** The retirement came first, so phase 0 needed no `svelte-stock` npm alias
   (RUNTIME open question 5): with the fork gone, `overrides.svelte` is gone and every package
   resolves the stock npm `svelte@5.57.2`.
2. **Package and subpath names** (RUNTIME open question 7): as proposed, `@svelters/native-runtime/core`
   (the compiler-facing contract, `src/core/index.js`), core internals in `src/core/internal.js`,
   the adapter `src/core/svelte.js`. Nothing in the repo contradicted it (N1 renamed tags and
   props, not packages).
3. **The contract is what the compiler emits**: 43 names (`packages/native-runtime/test/core-contract.mjs`
   reads them off the compiler's string literals). RUNTIME.md's list of 38/44 included `component`,
   which the compiler never emits (it uses `$n.component`).
4. **`@svelters/dom` (the DOM shim fallback): deleted.** Nothing on the compiled path uses it: the
   compiler emits host ops directly and never needs a DOM-shaped tree. Its only consumers were
   `@svelters/build`'s `SVELTERS_BACKEND=shim` and its own coercion test (the compiler now types
   static values from the spec).
5. **`@svelters/build`: kept, rewritten as the compiled app build.** Every fixture, gallery and
   bench still says `export default defineConfig(svelteConfig(import.meta.dirname))`; the hot
   reload tests and `pnpm watch` use its `svelters-build [--watch]` CLI. `svelteConfig(root,
   { toolkit, spec, dev })` now wraps `nativeConfig` + `svelteNative` from
   `@svelters/native-runtime/vite`; the toolkit comes from the app's `package.json`
   (`"svelters": { "toolkit": "qt" }`, default gtk). Keeping it kept ~45 app configs and the
   reload tests unchanged; the CL0 CLI can absorb it later.
6. **What `@svelters/renderer` owned that the compiled path still needs moved into
   `@svelters/native-runtime`:** the X6 styling runtime (`./style`: `registerStyles`,
   `setTokens`, `setColorScheme`, ...), the generated tables (`./bindings`:
   `src/bindings.generated.js`, of which the runtime uses `TOPLEVELS` and `ROW_OUTLETS`), the
   element typings (`./types`, `types/*.d.ts`, generated by `gen_backend.py`, `gen_bindings.py` and
   `examples/counter-qt/build.rs`) and the svelte-check of those typings (`check/`, now with
   `--diagnostic-sources js`: stock Svelte's compiler rejects `bind:text` on a native element, the
   TypeScript checks are what matter). Component helpers (`listen`, `NativeEvent`,
   `StaleHandleError`, `LISTEN_*`) were already in the runtime; components now import them from
   `@svelters/native-runtime` (the compiler recognizes that module instead of `@svelters/renderer`).
7. **`@svelters/lists`** keeps its name (the compiler recognizes `ListView` imported from it) but is
   a thin re-export of `@svelters/native-runtime/lists`; the keyed diff moved to
   `src/lists-diff.js`; the renderer-based `ListView.svelte`, controller and `RowHost` are gone.
   `@svelters/canvas`'s `draw` attachment now uses the runtime's `listen` and `set`.
8. **Compiled-path parity for what only the renderer did** (needed so no fixture, gallery page or
   e2e test loses its coverage; the compiler rejected them before):
   - **X7 toplevels anywhere**: `$n.toplevel(kind, present, show?)`. Inside an element a toplevel is
     inserted into the enclosing toplevel (transient) once the appends around it complete, and shown
     after that one; static `show="modal|modeless|none"` (`show_invalid` otherwise), dialogs default
     to modal (`TOPLEVELS`), windows to modeless. Before, a nested `<window>` compiled into a
     `host.insert(box, window)` and was never shown, and `show` was `unknown_property`.
   - **Attached kinds** (spec `attaches_to`): GTK `Gtk.EventController` kinds and `context-menu`
     (to `Gtk.Widget`), GTK `menu` (to `Gtk.MenuButton`), the Qt `construct.context_menu` element
     `menu` (to `QWidget`). Placed in any element of that kind when its slots do not take them,
     `$n.attached(kind)`, inserted with no slot or position, never the `before` of a sibling; next
     to text in a text-content element they are not content.
   - **Hand-written kinds in the specs** (`metadata/extras/<toolkit>-*.yaml` `elements[].spec`, read
     by `gen_semantics.py` after the GTK table cross-check): GTK `menu-bar`, `tool-bar`,
     `context-menu`, `menu`, `action`, `menu-separator` (`backend/menus.rs`) and `canvas`
     (`backend/canvas.rs`), Qt `canvas` (`canvas.hpp.in`).
9. **TestHost-vocabulary fixtures moved to real vocabulary.** `sync-handlers` and `listen-phases`
   used `key-pressed` on `<entry>`, which only the Node TestHost accepted (the compiled harness had
   a `testhost` overlay spec for them). They now attach an `<event-controller-key>` to the entry,
   compile against the real GTK spec, and the overlay and the harness's `testhost` target are gone.
10. **CSS scoping without the fork** (phase 0): `nativeSheets` compiles the component with stock
    `svelte/compiler` (`css: 'external'`) after blanking its `bind:` directives
    (`withoutBindings`): stock Svelte rejects native bindings (`bind_invalid_name`), and a binding
    never changes which elements a selector matches. Measured: the stock CSS output is
    byte-identical to the fork's for every styled component in the repo.
11. **Parser port**: the `customRenderer` `<svelte:options>` attribute (a fork addition in the
    verbatim port) and its `incompatible_with_custom_renderer` error were removed; stock Svelte
    reports `svelte_options_unknown_attribute`, and so does the port now.
12. **Fixture op logs regenerated on the compiled path.** Every `expected.oplog` was checked
    against the renderer's with `tools/oplog-compare.mjs` before it was rewritten: identical or
    state-equal at every boundary, except the reviewed differences listed in the completion record.

## Where the `svelters:gtk/<ns>` / `@svelters/types` alias wiring lives

Unchanged in substance: `typesAliases()` from `@svelters/types/vite` is applied by `nativeConfig` in
`packages/native-runtime/vite.js`, which `@svelters/build`'s `svelteConfig` now uses for every app.
`packages/build/index.js` no longer calls it directly.

### Fixture op logs: reviewed differences from the renderer's

`tools/oplog-compare.mjs` against the logs at bff6a637: 14 identical, 19 state-equal at every
boundary (op order only: keyed moves, the order of a flush's sets), 4 differing, all reviewed:

- `dialogs`: the TestHost records the transient insert of the nested window in the main window's
  default slot after the box (`[2, 6]`) where the renderer inserted it first (`[6, 2]`); the
  backends ignore `before`/slot for a transient insert (backend-abi.md "Toplevels in the tree").
- `menus`: `set #6 checkable true` where the renderer sent `""` for the bare attribute (a renderer
  bug: the compiler types it from the spec).
- `sync-handlers`, `listen-phases`: rewritten to the real GTK vocabulary (decision 9), so the key
  presses go to the attached controller (#5) instead of the entry.

### Found and fixed on the way (the full gates caught them)

- `buffer-bind` on GTK: `bind:value` was written before `lower`/`upper` (the compiler emitted
  bindings in source order), so GtkScale clamped the value to 0; the TestHost does not clamp, so
  the op logs looked state-equal. Bindings are now written after the element's other attributes.
- Qt gallery text page: borrowed nodes had no `setProp` (the renderer's nodes did); added (and to
  `NativeElement` in the typings).
- `bind:this` on a dynamic component left `$n.component(` unclosed (conformance sample
  `binding-property-non-reactive-ignored`); fixed, regression test in `rt1_kinds.rs`. Two more
  conformance samples now pass (`bind-this-proxy`, `bind-this-raw`).
- The core's fake `Boundary` lacked `get_effect_pending` (`$effect.pending()` inside a component
  would have thrown); `check-svelte-internals.mjs` now keeps the member list equal to Svelte's.

- `src/style.js` still carries the renderer's runtime setter-rule matching (`applyStyle`,
  `styleChildAttrs`, `explicitPropSet`); the compiled path matches setters at compile time and
  never registers rules, so that half is dead code now.

  `TOPLEVELS` and `ROW_OUTLETS` are used (it also still cross-checks bindings across toolkits,
  which test:meta relies on).
- The X7 `show` policy picks the modal method at run time from `TOPLEVELS`; moving it into the
  specs would let the compiler resolve it.
- `TestHost` records a transient toplevel insert as a slot child (see `dialogs`).
- Docs site: `concepts/abi.md` still describes `listen` flags and `call_sync` as planned (outside
  the guides this milestone rewrote). `docs/notes/native-compiler/language-subset.md` says
  `<script lang="ts">` is unsupported, which is out of date. `{await p}` in a template compiles
  without a diagnostic into an `await` inside a non-async effect (compiler bug, async is out of
  scope).

  the retired path; they are kept as history.
