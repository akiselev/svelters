# SV80: parenthesize object-literal arrow bodies in generated code

Fix lane, branch `ci/sv80-object-prop`, base master `01e8f677`.

**Status:** done; CI green on `de662522`, waiting for the coordinator's merge.

## The bug

A component prop whose value is a reactive object literal, `<Child props={{ a: x }} />`, was
memoized as `const $$prop1 = $.derived(() => { a: $.get(x) });`. The arrow body parses as a block
statement (`{ a: x, b: y }` is a syntax error, "expecting ';'"), so the whole module failed to load.
Stock Svelte emits `$.derived(() => ({ a: ... }))`.

## The fix (`crates/svelters-compiler`)

- `codegen::arrow_body_needs_parens(&Expression)`: true for a sequence or any expression whose
  leftmost token is `{` (an object literal, also as the object of a member/call, the left operand of
  a binary/logical, the test of a conditional, an object-pattern assignment, a postfix update).
- `codegen::arrow_body(&str)`: the string twin for bodies built as text (parenthesized when the
  text starts with `{`).
- Codegen: `thunk_body` uses the check; new `thunk_dynamic` for `Dynamic` values. Used by the
  component prop memo (the bug), template thunks, binding getters (`bind:`, `bind_link`,
  `bind:this` on elements and components). `paren_expr` also wraps a member/call led by `{`.
  Destructuring deriveds/thunks (`{#each}`, `{@const}`, snippets) and the script transform's
  destructured `$state`/`$derived` deriveds go through `arrow_body`.
- Other arrow sites (handler, render-argument and `{@const}` memos, block arguments, directives)
  already went through `paren_expr`, which wraps object literals.

## Tests

`crates/svelters-compiler/tests/sv80_arrow_body.rs`: object literal prop, nested object prop,
objects returned from a ternary (and a ternary whose test is an object), expressions led by an
object, `{@const}`/`{#key}`/`{#each}` with objects. Each output is also parsed with the crate's
acorn port. Failed on master (4 of 5: output does not parse), passes with the fix.

Run locally: only `cargo test -p svelters-compiler --test sv80_arrow_body`. Not run: everything
else (CI is the gate).
