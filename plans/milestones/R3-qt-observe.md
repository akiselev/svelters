## Mechanisms (backend.cpp.in, "property observation")

`b_observe(h, prop, on)` looks the property up in `kObsVia`, generated by `gen_cpp.py emit_observe` from every
`exact`/`partial` fact of `metadata/observe/qt.json` (Qt class + Q_PROPERTY, searched along the metaobject's
superclass chain), and installs every entry of the fact's `via` list the object supports. All of them live in one
`Observation` per (handle, prop) (refcounted; the host only sends transitions, but nesting stays safe).

| Mechanism | How | Removed by |
|---|---|---|
| `notify` | `QMetaObject::connect(obj, notifySignalIndex, relay, slot)` to a moc-less `PropRelay` holding ids only. A coarse NOTIFY (`QAction::changed()`, 14 props) gets one relay per observed prop, so it reports each covered prop once | deleting the relay (off, `destroy`, native death via `drop_listeners`); the sender's death disconnects it too |
| `bindable` | `QMetaProperty::bindable(obj).addNotifier(...)` kept as a `QPropertyNotifier` in the observation (`QTimer` interval/active/singleShot/timerType, `QSortFilterProxyModel`, animations, ...) | destroying the observation. **Pinned:** destroying a notifier after its object is safe: verify test `observe_runtime/bindable_notifier_outlives_object` (plain and through the backend), and the same scenario 100x with two notifiers under ASan (`-fsanitize=address`) against Qt 6.11.3 (SDK) and 6.12.0 (system): no report. In the backend the order is the safe one anyway: `destroyed` runs before `QObjectPrivate` (which holds the binding storage) is freed |
| `event` | one `ObsFilter` event filter per handle with a `QEvent::Type -> {prop: count}` table (`enabled -> EnabledChange`, geometry -> `Resize`/`Move`, ...) | the last event-based observation of the handle (the filter is deleted, which uninstalls it), or the handle |
| `signal` | another signal of the object through the same relay (O5 name pairs `<prop>Changed`/`<prop>Edited`, `textEdited`+`textChanged` for `QLineEdit:modified`, `modificationChanged`, `selectionChanged`, `blockCountChanged`, `pressed`/`released` for `QAbstractButton:down`) | as `notify` |
| deferred geometry | `timing: deferred` facts (`geometry`, `pos`, `x`, `y`, `size`, `width`, `height`, `rect`, `frame*`, `normalGeometry`): Qt sends `Resize`/`Move` to a hidden widget only at `show()`; the event mechanism reports them then | as `event` |
| metaobject fallback | a property without a fact (NT2 type kinds, reflected members): `hasNotifySignal()` -> NOTIFY, else `isBindable()` -> notifier (§5.1) | as above |

- A property with no installable mechanism is refused with `SVL_OBSERVE_UNSUPPORTED` (set_only, none); CONSTANT -1.
- **Threads (§5.6):** `notify_prop` hops with a queued `invokeMethod` on the application object when called off the
  GUI thread; the relay is a DirectConnection, the event filter and the notifier run on the object's thread.
- **Proportional props** (`QTextEdit` html/markdown/plainText, `QPlainTextEdit:plainText`): the backend does not report
  our own `set_prop` of the prop it is writing (§5.4; `g.setting`); cross-notified props still go through.
- **describe:** every element prop whose fact is exact/partial with a mechanism carries `SVL_M_OBSERVABLE` (236 props).
  `SVL_M_PROPORTIONAL` (R1, not on master yet) is not set: one line in `emit_describe` after the R1 merge.
- Debug hooks for the tests: `svl_qt_meta_prop_id` (metaobject id of a Q_PROPERTY no element exposes) and
  `svl_qt_observations` (observation and filter counts, for teardown checks).

## Rule O4 from the probe

The observe probe has an O4 section (`observe_probe.cpp` `o4()`): every writable QWidget-family property of shown
`QWidget`, child `QWidget`, `QLineEdit`, `QTextEdit`, `QPlainTextEdit`, `QSpinBox` set and set back, plus scenarios
(window state, move/resize while shown and hidden, activation, focus, parent enable/hide/show/font/palette/locale/...).
`observe_probe.py derive_o4` takes, per property, the change notifications (`*Change`, Show/Hide*, Move/Resize, Focus*,
Window(De)Activate) by specificity until every observed change is covered (minimum specificity 0.25). The result is
`o4` in `metadata/probe/qt/observe/6.11.3.json` (112 properties). `observe_rules.o4_table` uses it as the source of O4;
the ~34-entry hand table (`events:` in the rules) is the cross-check (per property in `_evidence.json` `o4`) and the
fallback for properties the probe never saw change.

| Cross-check verdict | Properties |
|---|---:|
| agree (same events) | 31: `enabled`, `font`, `palette`, `toolTip`, `cursor`, `layoutDirection`, `styleSheet`, `locale`, `acceptDrops`, `mouseTracking`, `tabletTracking`, `windowModified`, `focus`, `isActiveWindow`, `minimized`/`maximized`/`fullScreen`, the 11 geometry props, `readOnly` ×3 |
| differ | 1: **`QWidget:visible`**: hand `Show, Hide, ShowToParent, HideToParent`, probe `Hide, HideToParent, ShowToParent` (its minimal cover; `Show` adds nothing on the probed causes, including parent show). The probe's set is used |
| hand only (probe never saw it change) | 1: `QAbstractSpinBox:readOnly` (`ReadOnlyChange`): hand table kept, `origin: rule` |
| probe only, partial (some causes no event covers) | 7: `QWidget:childrenRect`/`childrenRegion` (`Resize`; a child's layout-direction change is not covered), `QWidget:sizeHint`/`minimumSizeHint` (`FontChange`; a frame/maximum change is not), `QTextEdit`/`QPlainTextEdit:textInteractionFlags` (`ReadOnlyChange`; a flag change that keeps read-only is not), `QDockWidget:windowTitle` (`WindowTitleChange`; `windowFilePath` sets are not) |
| probe: the property changes and no event announces it | 63 (e.g. `QLineEdit:placeholderText`, `QSpinBox:minimum`, `QWidget:statusTip`): `set_only` (O8) or `none` |

The hand table's `windowState` has no fact (not a Q_PROPERTY of the metadata).

## Verification (§4.5)

`tt_observe` (verify.cpp.in), one row per fact with a `verify` block, through the real ABI:

- **native set** (`change`: `QMetaProperty::write` of a new value; scalars, enums, flags and QRect/QRectF/QSize/QPoint/
  QPointF/QFont/QPalette/QCursor/QLocale/QSizePolicy/QColor/QUrl/QKeySequence) or **trigger** (`cross`: another
  property, or a C++ statement from the rules' `triggers`): at least one `prop_changed`, and the value really changed;
- **identical set**: none for `fires: on_change`, some for `on_set`;
- **coalescing** (backend side): 10 native changes leave only (h, prop) dirty;
- **user path** where a synthesizer exists (key/mouse events as QTest sends them: typing, Shift+Left, Ctrl+Z, Up,
  press/click): announced;
- **echo**: a proportional prop's own `set_prop` is not reported;
- **deferred**: a hidden widget's geometry change is announced at `show()`, not before;
- **teardown**: off, then a change: nothing; destroy while observed: the observation and the event filter go
  (`svl_qt_observations` back to its start count), and observing the dead handle fails;
- **class claims**: `silent` rows assert a partial fact's missed cause is not announced; `unsupported` rows assert
  the refusal, and for a writable `none` the native change happens and the metaobject has neither NOTIFY nor
  bindable (a verified `none`).

Rows on a class no element exposes reach the property by its metaobject id (`OB_META`) on the first plain element of
the class or a subclass (QWidget's `<widget>` is composite, so `QWidget:font` is checked on `<calendar-widget>`).
`examples/counter-qt/tests/observe.rs` `qt_bindable_and_event_properties_are_observed` is the acceptance test:
`QTimer.interval` through its notifier and `enabled` through `EnabledChange`, with off and destroy.

## Bindings through the facts

`gen_cpp.py Tests.promote_bindings`: a `bind:` fact whose property has an `exact` observe fact with a delivery row is
verified through that fact as well (the observe row joins its tests and fingerprint, `record.observe` names the fact),
so R2's lowering onto observation (§13 #8) rests on a ledger entry. The binding's own echo test stays (the renderer
keeps the signal plan as a runtime fallback). 32 of the 34 Qt binding facts are promoted; `group-box checked` and
`time-edit time` are `partial` and stay on their signal plan (the same 2 R2 keeps). Seven of the promoted ones
(`date-edit`/`date-time-edit` date, `list-widget current-row`, `current-index` of stacked-widget/tab-bar/tab-widget/
tool-box) were only `connect`-checked in R0 and now have a native trigger.
