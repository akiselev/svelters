## 0. Summary

1. **Zed's core lesson is the one we already built around: the UI thread never blocks, and every piece of state can be
   snapshotted cheaply and handed to a background thread.** SumTree/rope snapshots are an `Arc` bump; parsing,
   wrapping, LSP diffs and search run on snapshots; the UI waits at most 1–5 ms and otherwise shows an interpolated
   result (§2.4, §2.5). Our versions are the headless cores (berth-core, quire-core), `Snapshot` in quire, jobs that
   apply by version, and `logic`-only mutation (ARCH-EMBED §0.2). What we lack is **enforcement** (a lint, a hang
   watchdog, a frame histogram) and **a deterministic scheduler to test the async seams**.
2. **Testing is where Zed is furthest ahead of us.** Every async test runs on a seeded deterministic scheduler with a
   simulated clock, many iterations, `SEED=` replay, fake fs/LSP/git, and randomized multi-peer plans that are
   minimised on failure (§6). "We've been able to really lock things down and never have flaky tests on CI" (Sobo). Our
   isolates (ISO1), loader and HMR (Q1, H1–H3), jobs and quire's `Spawner` are exactly the code that needs it.
3. **Extensions: Zed chose WASM components for safety and versioned the WIT world per release, keeping every old
   version as an adapter** (§3). It still allows no UI panels after two and a half years, and its default capability
   grants are `*`. We contradict both deliberately: Svelte panels in isolates are our product, and the policy is
   deny-by-default (decisions, "Extensions"). The versioning mechanism is what we should copy.
4. **Settings: Zed's 2025 rewrite consolidated per-crate settings into one typed, schema-generated content struct
   with fallible per-field parsing, dated migrations and comment-preserving writes, after `Option<bool>`→`bool`
   broke auto-update for two releases** (§4). cadatomic's layered settings with provenance are ahead of Zed on
   provenance and policy, and behind on schema, migrations and the editor UI.
5. **Things already right in our plans that Zed confirms:** a retained model with effects queued and flushed after the
   update (ARCH-EMBED `logic`); hit-testing the previous frame (ARCH-SCENE §7.4); flexbox through taffy (GPUI1's
   Flutter-style layout was "strictly less powerful" and was replaced); query-driven tree-sitter features (quire);
   action ids with JSON-schema args and deprecated aliases (`cmd-arch`); idle = 0 frames (Zed moved to "present only
   during high-frequency input" in Dec 2025); building accessibility in from the start (GPUI went years without it, and
   Zed opts out of its own new AccessKit support).
6. **Our own history agrees.** old-cadatomic failed partly on an unsynced GPUI fork (`plan/01-overview.md` §8 rule 2);
   gpui.rs still says "For the near future, GPUI is tied to Zed". Nothing here argues for GPUI.
7. **Top 10** is §9; **do not copy** is §10.

## 8. Lessons and regrets, from the team

| # | Lesson | Source | For us |
|---|---|---|---|
| 8.1 | "couldn't make Atom better than the platform it was built on"; a Rust core under Electron still "just couldn't achieve the performance" | `blog/zed-1-0`; `blog/we-have-to-start-over`; Changelog #531 | Our stack (Rust shell, egui, QuickJS for panel logic only) keeps the platform ceiling ours; keep JS off every per-frame path (ARCH-SCENE §0.7: 0 JS per scrolled row) |
| 8.2 | "With Atom it always felt like we didn't know where to look for performance." | `blog/we-have-to-start-over` | Per-root frame-budget attribution (ARCH-EMBED §0.3) is the answer; make it visible in a dev overlay |
| 8.3 | Atom's buffer was an array of lines; off-thread work needed C++ shared memory. | 8.4 | "if you're rewriting something someone else wrote, be doubly suspicious of yourself" [verbatim] | `blog/we-have-to-start-over` | Applies to Monaco ports: keep the test-first rule (`editor` §0) |

| 8.6 | "Loading things at runtime didn't make us faster at developing" (JSON themes from TypeScript) | `blog/why-the-big-rewrite` | Hot reload pays only when the reloaded thing is where the work happens (component + style together). Tokens files should stay small and typed |

## 10. Things Zed does that we should deliberately not copy

| Zed | Why not for us |
|---|---|
| Rebuilding the element tree every frame on an arena (GPUI's view layer) | Our scene is retained and driven by Svelte signals and Rust setters; per-frame rebuild would put JS or Rust render code on every frame. Keep GPUI's *caching* ideas only (§1.3) |
| Its own GPU renderers per platform (Metal, DX11, wgpu) and its own text system | egui + wgpu + egui's text stack (parley as fallback) is decided; Zed itself moved Linux to wgpu |
| Wide-open default extension grants (`process:exec *`, `download_file *`, `npm:install *`) | Deny-by-default is the user's decision; Zed's own docs say restricting later breaks extensions |
| No UI extensibility | Svelte panels in isolates are the product. Constrain with declared slots and stripe slots (`shell` §4) instead |
| Extension kinds for things a protocol registry serves (slash commands, agent servers, MCP servers), later removed or deprecated | Use MCP/ACP-style registries for those; keep extension kinds for UI, data and compute |
| A git monorepo of submodules as the extension registry, with a one-to-two-month review backlog | "It doesn't scale"; cadatomic's marketplace (CE5) should be a service with CI-built artifacts from the start |
| SQLite for layout and pane trees | berth's JSON file is diffable, lintable, schema-checked and distributable through the hub (D6); keep a database, if any, for history and caches |
| Panel dock positions stored in settings | Layout lives in berth's file and workspace overlays; settings stay settings |
| `f32` flex weights in the pane tree | berth's integer shares are deterministic and round-trip exactly |
| Copying Zed's CRDT, rope or editor code | GPL-3.0; learn from the posts. Our CRDT step (CE9) should evaluate existing CRDT crates behind quire's `Text` facade first (**verify** candidates at P3) |
| Source-location element ids (`text!()`) for accessibility | Collide in lists and drop nodes silently; we use explicit anchors and author ids (EM1) |
| Re-entrant update panics (leasing) as the ownership model | Our queued `logic` phase gives run-to-completion without runtime panics |
| Blocking the UI thread on background work with a timeout (`block_with_timeout`) | Caused the 4.5 s beachball; allow only ≤1 ms waits on higher-priority tasks (§1.10) |
| Telemetry and crash uploads to the vendor's pipeline (Sentry, Snowflake, Amplitude) | High-security users: opt-in, local first, and routable to the operator's own server through U5 |
| Chat and channels inside the editor | Zed scaled them back; keep collaboration to editing and review |
